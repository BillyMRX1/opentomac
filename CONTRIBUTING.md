# Contributing to opentomac

Thanks for your interest in opentomac, a local-first continuity app that links an Android phone with a Mac over the local network with no account and no cloud relay. Contributions of all kinds are welcome: bug reports, device testing, documentation, and code.

## The clean-room rule (read this first)

opentomac is a clean-room project built from public product information only. To keep it that way, contributions must not include:

- decompiled, disassembled, or leaked source code from any proprietary app
- proprietary protocol captures, assets, icons, or trademarked names
- anything you learned under an NDA

If a contribution needs knowledge of how a proprietary product works internally, it cannot be accepted. Public documentation, your own reverse engineering of your own device's open interfaces (Android SDK, macOS SDK), and independent design are all fine.

## Getting set up

Prerequisites:

- JDK 21
- Android SDK (platform 35, build-tools 35), with `sdk.dir` set in `local.properties`
- For the Mac app: an Apple Silicon Mac, Xcode 15 or newer, and [XcodeGen](https://github.com/yonaskolb/XcodeGen) (`brew install xcodegen`)

The Gradle wrapper pins Gradle 8.13; use `./gradlew`, never a system Gradle.

## Repository layout

| Path | What lives there |
| --- | --- |
| `shared/` | Kotlin Multiplatform module: wire protocol, framing, cryptography, pairing and trust, session manager, clipboard/transfer/notification/media engines. Targets: `android`, `jvm` (tests), `macosArm64` (dynamic framework consumed by the Mac app). |
| `android/` | Jetpack Compose app with a foreground connection service and the `AppRuntime` orchestrator. |
| `macos/` | SwiftUI app over the Kotlin/Native `MacController`. The Xcode project is generated by XcodeGen from `project.yml` and is not checked in. |
| `scripts/` | Build helpers, notably `build-macos.sh`. |
| `packaging/homebrew/` | Cask source of truth for the `billymrx1/opentomac` tap. |

Everything protocol-critical belongs in `shared/` with tests. The platform apps should stay thin: platform integrations (clipboard, notifications, key storage) implemented behind interfaces the shared module defines.

## Building and testing

Shared core tests (the main test suite, currently 188 tests):

```
./gradlew :shared:jvmTest
```

Note: the `TcpTransportTest` cases open real localhost sockets, so they fail in sandboxes that block loopback networking.

Android debug APK:

```
./gradlew :android:assembleDebug
```

macOS app (links the KMP framework, generates the Xcode project, builds):

```
./scripts/build-macos.sh
```

Always relaunch the built Mac app with `open path/to/Opentomac.app`. Launching the binary directly from a terminal starts the app without its TCP listener and pairing will fail with connection refused.

## Making changes

- Changes to `shared/` need tests. Bug fixes should come with a test that fails without the fix.
- App-layer changes benefit enormously from a note about real-device testing: which phone, which macOS version, what you exercised.
- Match the existing style of the file you are editing. Kotlin follows the official style; the Mac app uses the design tokens in `macos/Sources/DesignTokens.swift`; the Android theme lives in `android/.../ui/theme/`.
- Write comments only for constraints the code cannot express on its own. This codebase leans on a few such comments heavily (nonce ordering, PII clearing, backoff rules); keep that signal-to-noise ratio.
- Do not add product features that require a cloud service, an account, or a relay. Local-first is the design contract, not an implementation detail.

### Sharp edges worth knowing

- Clipboard send order must match sequence order; the receiver drops out-of-order items. All sends are serialized by a mutex; do not bypass it.
- On Kotlin/Native, okio's `use {}` needs an explicit `import okio.use`. JVM-only compilation will not catch a missing one.
- JUnit 4 test methods must return `Unit`: write `fun x(): Unit = runBlocking { ... }`.
- Never send unbounded reads of Android content URIs; image handling downscales to JPEG at 3 MiB / 2048 px maximums.

## Commits and pull requests

- Use conventional commit messages with a scope, in the imperative: `fix(clipboard): ...`, `feat(mirror): ...`, `docs: ...`.
- Keep PRs small and focused. One logical change per PR.
- CI must pass (`:shared:jvmTest` and the Android build run on every PR).
- Describe what you tested and on which devices.
- Commit types drive automated releases via release-please: `feat` bumps the minor version, `fix` bumps the patch version, and a release ships when the maintainer merges the bot's release PR.

## Reporting bugs and security issues

Open a GitHub issue for bugs; include both device types, OS versions, and steps to reproduce.

For anything security-sensitive (the handshake, session encryption, pairing, trust storage), please do not open a public issue. Use GitHub's private vulnerability reporting on this repository so a fix can land before disclosure.
